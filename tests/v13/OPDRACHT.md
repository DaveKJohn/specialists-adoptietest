## Test A — INSTALL, alleen met de QUICKSTART

Je krijgt één ding: het document. Per stap: wat deed je, wat kwam eruit, wat voorspelde het document, en kon
je verder. Bij een reparatie: **werkt hij?**

### A0 — hoe kom je er überhaupt?

Via welke route kom je binnen, en hoeveel beslissingen zitten er vóór stap 1? Groen in v11 en v12; de vraag is
of dat zo blijft.

Claude Code aanwezig, de PowerShell `ExecutionPolicy`, PATH plus een volledige editor-herstart. **Zeg eerlijk
welk deel je opnieuw hebt gemeten en welk deel al stond** — in v10, v11 en v12 stond alles al, en "groen
(tekst)" is dan het hoogst haalbare.

### A1 — het settings-fragment *(#335)*

Plak het blok letterlijk in een leeg bestand en parse het. Weet je waar `.claude/settings.json` staat, en dat
je die map zelf moet aanmaken?

### A2 — de twee commando's *(#329, weg sinds v12 — blijft hij weg?)*

Op een maagdelijk profiel faalde `claude plugin marketplace update` in v10; sinds het document de registratie
ervóór zet en één herstart voorschrijft, werkte het in v12 (`✔ Successfully updated marketplace`). **Loopt het
weer door?**

- **Kleine v12-observatie, nog niet gerepareerd:** bij de #329-fout drukt de pagina
  `Available marketplaces: claude-plugins-official` af. Op een écht maagdelijk profiel is die lijst **leeg**.

- **#336** — SHA256 van `settings.json` vóór en ná `install --scope project`, mét de key al aanwezig. v12 mat

- **#325** — één install tegen een `project`-record en één tegen een `local`-record: de query moet
  respectievelijk **één** en **twee** regels geven.

### A3 — herstart, de verificatiequery en de tagvergelijking *(#372 — DE stap van deze ronde)*

De query zelf was groen in v10 t/m v12, inclusief het `payload`-veld van #355. Noteer of je
`payload present` krijgt en of je uit `version` en `gitCommitSha` kunt aflezen welke code je draait.

**Dan de tagvergelijking, en die is deze ronde de kern.** v12 vond twee dingen in het `#322`-blok van de
`specialists-init`-skill: de clausule *"`main` only, no tags"* was onwaar (zijn verse clone droeg `v3.1.1`), en
— erger — de release-tags zijn **geannoteerd**, dus `git rev-parse v3.1.1` slaagt en geeft het **tag-object**
in plaats van de commit. De vergelijking mislukt dan terwijl je er precies op staat. Het document hoort nu:

- de valse *"no tags"*-clausule **niet meer** te bevatten (ook niet in de vorm *"a shallow, tag-less clone"*),
- een **derde** uitkomst te noemen naast "gelijk" en `fatal: ambiguous argument`: **slaagt, maar geeft het
  tag-object**, en
- expliciet te zeggen: **peel met `^{}`** als je een tag lokaal resolvet, en dat de `gh api …/tags`-route
  immuun is omdat `.commit.sha` de commit al is.

**Meet het in deze volgorde en schrijf alles op:**

```powershell
# in ~/.claude/plugins/marketplaces/davekjohns-workshop
git rev-parse HEAD
git tag                      # hoeveel tags draagt jouw clone?
git cat-file -t v3.1.2       # 'tag' = geannoteerd
git rev-parse v3.1.2         # het tag-OBJECT
git rev-parse "v3.1.2^{}"    # de COMMIT
```

**Dit is de eerste ronde waarin je clone niet op de release-commit staat** (`main` ligt vóór `v3.1.2`, zie de
kop van dit document). De juiste conclusie is dus *"ik draai `main`, drie commits ná de release"* — en de
vraag is of het document je daar komt, of dat je met de niet-gepeelde vergelijking op een **verkeerde reden**
voor een terecht verschil uitkomt. Noteer ook of jouw clone shallow is en welke refspec hij heeft.

### A4 — stap 2, de bootstrap *(en de meting die twee rondes is blijven liggen)*

**Doe dit deze keer via de skill, interactief.** v11 en v12 draaiden `bootstrap.ps1` allebei direct, omdat
`claude -p "/specialists-init"` op de permission-classifier stukliep — dus het pad dat de QUICKSTART
voorschrijft is **nog nooit gelopen**. Start een interactieve sessie en roep `/specialists-init` aan.

- **Lukt het?** Noteer wat de skill print en of de `Done:`-regel klopt met wat de pagina belooft. Jouw repo is
  vers, dus je hoort `2 script-scaffold(s) created, 0 already present` te zien (#358, geverifieerd in v12).
- **Lukt het niet?** Schrijf **letterlijk** op waar het op stukloopt en welke melding je krijgt, en laat de rij
  op **niet gemeten** staan. Val daarna terug op `bootstrap.ps1` direct, zodat de rest van de ronde doorgaat —
  maar noem de wrapper dan niet groen op grond van het script eronder. **Zeg ook of dit een harnasgrens is of
  een bevinding over de plugin**; dat onderscheid is het halve resultaat van deze stap.
- **#363 / #333 / #337.4 / #337.2** — alle vier groen in v12: de hook-stub is zichtbaar een placeholder met
  slotregel, en de sessie ná de bootstrap geeft nul `[ERROR]`-regels plus precies één niet-tellende
  `[ROSTER-PENDING]`. Controleer of dat zo blijft; het is een regressiecheck, geen nieuwe meting.

## Wat deze ronde bewust niet doet

Schrijf dit over in het rapport, zodat de bron weet wat er **niet** gemeten is en het niet als groen leest.

| Niet in scope | Waarom |
|---|---|
| De teardown-regressie in twee cycli | Dat is de **bezette**-consumertest. v13 is de verse; `life-hub` wordt niet aangeraakt |
| Een vers **apparaat** | Zelfde machine, CLI, git en OS. Dit is een verse **gebruiker** |

Twee van `v3.1.2`'s reparaties zitten volledig aan de bronkant: de craft-regel van [#378](https://github.com/DaveKJohn/davekjohns-workshop/issues/378) en poort 16 van [#379](https://github.com/DaveKJohn/davekjohns-workshop/issues/379). Hier per definitie niet te zien |

| De aantallen-sweep door de documentatie | v13 meet het pad en de vier reparaties, niet of elk getal in elk document klopt |
| Het #283-CRLF-artefact | Deze repo heeft geen `.gitignore`. **Bouw er geen** — een oneerlijke fixture is geen meting |
